# Shopify-native Purchase attribution

The Google & YouTube app remains the only Purchase sender: `AW-18501766604/Ig36CKDCy6MdEMybqvZE`. This change adds native Shopify consent and a consent-gated storefront Google linker. It adds no purchase event, matching uploader, audience, GA destination, custom consent store or consent UI.

**Supported route.** Hydrogen 2026.10 supports Next.js and provides `ShopifyScripts` with the default hosted Shopify banner. A restricted same-origin proxy uses Shopify's official request handler; only consent queries reach Shopify, without private credentials, landing URL, referrer, email or unrelated application cookies. Shopify owns the UI and its opaque consent persistence. The footer's Cookie preferences link reopens that native UI. The empty analytics storefront ID omits Hydrogen's optional performance beacon; Shopify analytics destinations and WebMCP are disabled.

At checkout preparation, Shopify's documented `@inContext(visitorConsent: ...)` cart query produces a fresh checkout URL. Its `_cs` and all other checkout parameters are preserved. The bag and review page render a real anchor after preparation. Cart mutations, native consent events, focus and page restoration invalidate preparation. Pointer, keyboard and click handlers recheck the current cart revision and native purpose flags before navigation. GPC suppresses marketing and sale-of-data both in the browser and, when its header is present, the checkout API. Failed consent loads use denied flags. A blocked Google script does not prevent checkout.

The Google tag loads only on the three advertised product paths and a small set of clean browsing/review paths, after Shopify allows marketing and sale-of-data and GPC is absent. Other routes and unknown query parameters cannot initialize it. A document navigation unloads an existing tag before sensitive SPA paths are written to history. Attribution cookies can survive ordinary browsing; checkout from an excluded product returns through the safe review page. Withdrawal deletes this integration's `_gcl_*` cookies and reloads to unload the tag. Native Shopify consent cookies are never edited by application code.

**Actual vendor behavior.** The tag uses `send_page_view:false`, denied analytics/personalization, `allow_ad_personalization_signals:false`, disabled Google signals and enhanced conversions, and a fixed clean referrer. An empty referrer allowed the current vendor runtime to fall back to the real sensitive referrer; the fixed origin avoids that. Tests still observe standard Ads `ccm/collect` page-view attribution pings with `npa=1`. These are not configured as conversions. Do not describe this as zero Google traffic after consent. Template permission policies are defense in depth, not proof that all Google built-ins stop reading the DOM. Approved native app handling remains unchanged.

The existing Meta pixel independently reads the same native marketing/sale permission and GPC gate before its script or event queue can initialize. Its ID, payloads, explicit PageView/ViewContent/AddToCart events and protected-route exclusions remain. Native withdrawal clears unsent events and Meta cookies, revokes consent, and reloads to unload the old runtime; current product views resume after native grant without replaying denied cart actions. This is independent of the Google route allowlist.

The browser suite starts the production Next build on loopback, intercepts every browser request, serves archived unmodified Shopify/Google scripts, and replaces Shopify's server API with a synthetic upstream. All non-fixture external browser traffic is aborted. `tests/fixtures/google-attribution/sources.json` records source URLs and SHA-256 hashes. Screenshots and request traces default to `/tmp/iqon-google-attribution`; set `E2E_SCREENSHOTS` to retain them elsewhere. `CHROME_PATH` can select a locally installed Chromium. No purchase callback is invoked by the browser suite. Meta loader lifecycle tests use a queue-draining recorder instead of the live Meta vendor runtime; they prove gating, cancellation, queue handling and event deduplication, not live Meta network receipt.
